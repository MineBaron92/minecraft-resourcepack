## 1단계: 조립

- 29개 PNG 중 7개(`neckwear, footwear, tail, wings, objects, eyewear, earwear`)는 불투명 픽셀이 0개라서 제외했습니다.
- `layout.json`은 신뢰하지 않고 비교용으로만 썼습니다. 실제로 틀린 값이 많았습니다. 얼굴이 0.8배로 축소돼 있었고, 팔이 캔버스 오른쪽 밖에, 홍채·눈썹이 (0,0) 근처에 놓여 있었습니다.
- 배치 방법: 전체 캔버스 레이어는 원위치(±픽셀 탐색으로 확인)에 두었습니다. 크롭된 레이어는 다른 레이어에서 구한 탐색 영역(얼굴 안의 눈 밴드, 몸통 옆의 위팔) 안에서 템플릿 매칭으로 초기 위치를 잡았습니다. 그다음 **실제 합성 렌더와 원본의 오차**를 줄이는 국소 탐색(위치·스케일·팔 회전)으로 다듬었습니다.
- **뒷머리 버그 수정**: `back_hair` 한 장에는 머리 뒤 덩어리(몸 뒤에 와야 함)와 어깨 위로 내려오는 앞쪽 가닥(몸 앞에 와야 함)이 함께 들어 있습니다. 그래서 드로우 오더 하나로는 맞출 수 없습니다. 몸과 겹치는 픽셀마다 원본 색이 머리와 몸 중 어느 쪽에 가까운지 비교해서 `back_hair_back` / `back_hair_front` 두 장으로 자동 분리했습니다.
- 눈: 속눈썹·흰자·홍채를 눈 영역 안에서 전수 격자 탐색(위치 ±10px, 스케일 ±16%)으로 함께 맞춥니다.
- 드로우 오더: 겹침 투표로 초기 순서를 만들고 렌더 오차 기준 hill-climbing으로 조정했습니다. 의미상 위반(홍채가 얼굴 뒤로 숨는 경우 등)은 강제 제약으로 막았습니다.
- 가시성 트림: 합성 결과에서 보이지만 원본에는 아래 레이어나 배경이 보이는 픽셀은 투명 처리했습니다(지우기만 하고 칠하지는 않음). 영향을 받은 것은 팔 레이어 약 660px뿐입니다.

| 원본 CG 대비 | PSNR | SSIM | MAE |
|---|---|---|---|
| 기존 `layout.json` 배치 (공식 position_parts) | 16.0 dB | 0.888 | 13.8 |
| **이번 결과 (Spine 런타임 렌더, setup pose)** | **32.8 dB** | **0.990** | **0.93** |

Spine 런타임 렌더와 1단계 합성의 차이는 54.9 dB입니다. 메쉬·가중치·아틀라스 변환에서 외형이 바뀌지 않았다는 뜻입니다.

## 2단계: 리깅

```
root ─ hip ─ spine ─ chest ─┬─ breath (호흡 스케일 전용 리프, 자식에 스케일 전파 안 됨)
                            ├─ breast_r / breast_l (흉부: 상체와 독립된 이동·회전·물리)
                            ├─ arm_{r,l}_up ─ arm_{r,l}_low
                            └─ neck ─ head ─┬─ eye_r / eye_l (깜빡임)
                                            ├─ bang_r / bang_c / bang_l (앞머리)
                                            ├─ hair_r1─r2─r3─r4, hair_l1─l2─l3─l4 (옆·뒷머리 가닥)
                                            └─ hair_b1 ─ hair_b2 (뒷머리 덩어리)
       spine ─ shirt_r / shirt_l (셔츠 자락)      hip ─ thigh_r / thigh_l
```

- 피벗은 모두 레이어에서 자동으로 측정했습니다. 엉덩이·허리·가슴은 하의·상의 bbox 비율, 가슴 중심은 셔츠의 블러시(분홍) 클러스터 중심, 머리카락 체인은 가닥 중심선, 앞머리는 열 단위 하단, 팔은 1단계에서 찾은 포즈를 썼습니다.
- 가중치 메쉬 9개(뒷머리 2장, 앞머리, 상의, 하의, 레그웨어, 목, 양팔)는 격자 메쉬입니다. 가중치는 허용된 본 선분까지 거리의 가우시안 감쇠로 계산하고, 정점당 최대 4본으로 정규화했습니다. 앞·뒤로 나눈 뒷머리는 같은 가중치 함수를 쓰므로 움직여도 이음매가 생기지 않습니다.
- 얼굴 부품(눈·코·입·눈썹·귀·머리띠)은 head/eye 본에 붙인 리지드 리전입니다.

## 3단계: 애니메이션 (8초 루프)

- `idle`: 호흡 2회(가슴 리프트, breath 본 스케일), 몸 흔들림, 목·머리의 지연된 역방향 움직임, 팔의 미세 움직임, 눈 깜빡임 3회.
  머리카락·앞머리·흉부·셔츠 자락의 탄성 움직임은 1차 모션이 만드는 가속도로 감쇠 스프링을 시뮬레이션하고, 그 결과를 키로 구워 넣었습니다. 정상상태 주기를 사용했고 루프 이음매는 MAE 0.4입니다. 물리를 지원하지 않는 런타임에서도 동일하게 재생됩니다.
- `idle_physics`: 1차 모션만 키로 넣고, 2차 모션은 Spine 4.2 물리 제약(런타임 시뮬레이션)이 담당합니다. 두 애니메이션은 각자 물리 mix를 0과 1로 키잉하므로 2차 모션이 이중으로 적용되지 않습니다.

## 바스트 모핑 (`bust_bounce`)

레퍼런스 영상의 움직임을 광류(optical flow)로 측정한 뒤 그 특성에 맞춰 만들었습니다. 캐릭터는 원래 디자인대로 옷을 입은 상태 그대로입니다.

- **리그**: 좌우 각 2본입니다. `breast_X`는 위쪽 부착점에서 흔들림(회전)을, `breast_X_tip`은 질량 중심에서 바운스(이동)와 스쿼시/스트레치(스케일)를 담당합니다. 상의 메쉬는 9px 격자(약 1,800 삼각형)로 촘촘하게 했고, 가중치는 `verification/bust_weight_map.png`에서 확인할 수 있습니다.
- **시뮬레이션**: 가슴 부착점의 관성 가속도로 구동되는 비선형 2D 스프링입니다.
  - 들어 올리는 방향이 처지는 방향보다 단단합니다.
  - 변위가 커지면 강성이 커지는 3차 항을 넣어, 크게 떨어질 때 탄력 있게 튀어 오르되 발산하지 않습니다.
  - 감쇠비는 0.12 정도로 낮아 여러 번 되튑니다.
  - 좌우 진동수를 약 4.5% 다르게 해서 위상이 자연스럽게 어긋납니다.
  - 안쪽 충돌 제한으로 양쪽이 서로를 통과하지 않습니다.
  - 변위는 부피를 대략 보존하는 스쿼시/스트레치(0.83~1.21)로 변환됩니다.
- **구동 모션**: 3.2초 주기 2회(6.4초 루프)입니다. 천천히 들어 올렸다가 잠깐 멈추고, 중력처럼 가속하며 떨어진 뒤 살짝 아래로 지나쳤다가 안정됩니다. 낙하할 때 좌우 킥을 주기마다 번갈아 넣어 좌우 반응이 달라지게 했습니다. 머리와 목은 0.12초 늦게 따라옵니다.
- **레퍼런스 비교** (같은 광류 측정 방식):

| | 레퍼런스 | `bust_bounce` |
|---|---|---|
| 몸통 대비 상대 바운스 진동수 | 1.02 Hz (1.0~1.4 Hz 대역) | 1.25 Hz |
| 되튐(0 교차) 횟수 / 초 | 1.9 | 2.6 |
| 고주파 진폭 / 가슴 크기 | 0.014 | 0.032 (요청대로 더 강하게) |

- `bust_bounce`는 구운 키 버전이라 모든 런타임에서 동일하게 재생됩니다. `bust_bounce_physics`는 1차 모션만 키로 넣고 Spine 4.2 물리 제약이 실시간으로 반응합니다.
- `idle`에도 같은 스프링 모델을 약한 구동(최대 변위 0.05R)으로 적용했습니다.
- 영상: `verification/bust_bounce.mp4`, `verification/bust_bounce_closeup.mp4` (30fps). `preview.html`의 기본 애니메이션도 `bust_bounce`로 바꿨습니다.
- 한계: 셔츠 무늬와 멜빵이 상의 레이어에 합쳐져 있어 가슴과 함께 늘어납니다. 천이 미끄러지는 표현은 없습니다. 형태 변화는 본 스케일 기반이라, Live2D 수준의 정교한 디포머(그리기 단위 형태 키)만큼 세밀하지는 않습니다.

## 검증 방법

`spine_pipeline/verify/render_frames.mjs`가 공식 `@esotericsoftware/spine-webgl@4.2.74`로 headless Chromium에서 setup pose와 두 애니메이션을 10fps로 렌더링합니다. 로딩 오류는 0건이었습니다. `preview_offline.html`도 Chromium에서 "Loaded successfully"를 확인했습니다.

## 구현하지 못한 것 / 한계 (명확히)

1. **팔은 실제로 굽힐 수 없습니다.** CG에서는 손이 등 뒤로 가 있지만, 분리된 팔 레이어는 곧게 편 팔입니다. 그래서 위팔 부분만 맞추고, 보이면 안 되는 아래팔은 트림했습니다. 큰 팔 동작(손 흔들기 등)은 불가능합니다. 소매 가장자리에 계단 모양이 조금 남아 있습니다.
2. ~~오른쪽 눈(화면 기준) 흰자 어긋남~~: **수정 완료.** 흰자는 대부분 홍채·속눈썹 아래에 가려져 있어서 국소 탐색이 잘못된 위치에 머물렀습니다. 이제 눈마다 속눈썹·흰자·홍채를 전수 격자 탐색으로 함께 맞춥니다(`eye_group_search`). 눈 영역 오차는 오른쪽 8.1→2.2, 왼쪽 3.7→1.8입니다.
3. **귀와 눈썹은 원본에서 머리카락에 완전히 가려져 있습니다.** 위치는 기하학적으로 추정했고(얼굴 옆, 속눈썹 위) 원본으로 검증할 수 없습니다.
4. **깜빡임은 eye 본 scaleY 압축 방식입니다.** 감은 눈 이미지가 없어서 눈꺼풀 형태를 바꾸지는 못합니다.
5. **의상 흔들림은 제한적입니다.** 셔츠·바지가 몸에 붙는 디자인이라 자유롭게 펄럭일 부분이 없습니다. 셔츠 자락 본 2개, 흉부 본의 셔츠 메쉬 변형, 호흡 스케일로 표현했습니다. 멜빵은 상의 레이어에 합쳐져 있어 독립적으로 움직이지 않습니다.
6. **메쉬는 격자 메쉬입니다.** 윤곽을 따르는 메쉬나 에디터식 자동 가중치(heat diffusion) 수준은 아닙니다. 투명 영역 일부도 삼각형에 포함됩니다.
7. **물리 제약(`idle_physics`)의 강도·감쇠는 경험값입니다.** 구운 `idle`과 완전히 같은 움직임은 아닙니다. 1차 모션이 작아서 런타임 물리 반응도 작습니다.
8. 다리는 CG 하단에서 잘려 있어 하체 애니메이션(걷기 등)은 범위에 넣지 않았습니다.
9. Spine 에디터 자체로 열어 보는 확인은 이 환경에서 할 수 없었습니다. 검증은 공식 런타임으로만 했습니다.

## 재생성

```bash
pip install numpy pillow opencv-python-headless
mkdir -p /tmp/spnode && cd /tmp/spnode && npm i @esotericsoftware/spine-webgl@4.2.74 @esotericsoftware/spine-player@4.2.74 playwright-core@1.56.0
NODE_DIR=/tmp/spnode CHROME=/path/to/chrome bash spine_pipeline/run_all.sh
```

`spine_pipeline/vendor/`에는 공식 spine-animation-ai 스크립트 사본이 있습니다(PolyForm Noncommercial 1.0.0 라이선스, 비상업적 용도).
